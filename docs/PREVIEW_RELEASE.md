## Tanuki Rush — Android preview

Try the offline downhill runner with daily missions, leaf-token rewards, unlockable cosmetic boost trails, ranks and local best times.

**Preview 1.0.7:** Still no new gameplay — this build exists to answer one question. When the app hangs on the blue screen, 1.0.6's watchdog could only say that no frame arrived; it could not say whether the phone's main thread was blocked or whether the machine was simply too slow to do anything. 1.0.7 writes a **heartbeat to the log every 5 seconds** while it waits, so a captured log now separates those two cases, and the CI boot test reports how long the emulator itself took to become ready. Nothing visible changes: if the hang happens you still get the same on-screen explanation with your device details and Retry/Close. If you can connect the phone to a Windows PC by USB, `tools/field_diag.ps1` collects everything (screen colours, logs, WebView and GPU details) in one run. **Two extra arm64 APKs are attached to this release for that diagnosis:** `tanuki-rush-arm64-release-impeller-off.apk` (Flutter's alternative rasterizer disabled — if the game appears with this one, the rasterizer was the cause) and `tanuki-rush-arm64-debug-inspectable.apk` (a debug build, so Chrome's `chrome://inspect` on a PC can read the WebView console and the canvas state). Both come from the same build and share a signing key, so you can switch between them without uninstalling; moving to them from an older preview does require one uninstall, which erases local progress. Neither changes what is shipped: the normal `tanuki-rush-android-preview.apk` still uses Flutter's defaults.

**Preview 1.0.6:** No new gameplay — this build is about the blue screen. 1.0.5 promised that fix and did not deliver it: the hang happens *before* Flutter draws anything, so no Dart-side timeout or error screen can ever appear, and what you saw was the plain Android window background. Automated testing reproduced it once — the same APK that painted its first frame on an Android 14 (API 34) emulator never painted on an Android 16 (API 36) one — which rules out a bad download or a damaged install. Since then the same hang has appeared once on an Android 14 emulator that had passed three times, so it is intermittent rather than tied to one Android version — and it may be a startup race any device can hit. Four consecutive passes on the newer image are encouraging but prove nothing on their own, so **treat the hang as unfixed**. What 1.0.6 does guarantee is that the screen is never silently dead again: a **native** watchdog, which runs even when Flutter does not, shows your phone model, Android version, API level and how long it waited after 12 seconds, with **Jaribu tena / Retry** and **Funga / Close**. If you see that screen, please photograph it and report exactly what it says; Android 17 has no CI emulator image, so those details are the only evidence available for the newest phones.

**Preview 1.0.5:** Fixes the startup hang some 1.0.4 installs hit, where the app sat on an empty blue screen and never woke up. The app now always draws its first screen, every startup wait has a timeout with a visible error and retry, and every APK is boot-tested on an emulator before it can become a release. If 1.0.4 never opened on your phone, uninstall it and try this build, then report whether it opens plus your phone model and Android version.

**Preview 1.0.4:** Android progress and settings now use a private offline SQLite database. Open **Settings → Device storage → Details** for native storage status. An in-place update from the same fixed-origin build and signing key migrates the old save once; startup stops rather than silently replacing data if the save cannot be opened. The Three.js game still runs in a WebView, and there is no Supabase connection or cloud sync.

A crash or fall shows Game Over. Choose **REVIVE FREE** once per run to continue from the last checkpoint with your score and leaves, or **RETRY FROM START**. Collected leaves no longer absorb crashes; BOOST can still smash obstacles. No payment, ads or internet connection are needed for the revive.

The BOOST sound has been made quieter and simpler, and the music scheduler has more time to handle brief frame stalls. The earlier automatic audio recovery and **Pause → Settings → Restore Audio → Reset** remain available. Browser tests monitor music and output during a held BOOST, repeated taps and a simulated stall, but they did not reproduce the reported Pixel audio loss. **Please test on the physical phone; this is not a confirmed device fix.** Steering by holding and dragging on the left half remains included.

**Install:** Download `tanuki-rush-android-preview.apk` on an Android phone, open it, and allow installs from that source if Android asks. The APK supports arm64 and armv7 devices. `SHA256SUMS.txt` is provided to check the download.

**Important:** This is an early, debug-key-signed preview, not a production/Play Store release. Different CI builds may have different debug signing keys. If Android requires you to uninstall the old preview first, its saved progress may be erased and the migration cannot recover it. There is no built-in export: **do not uninstall a build containing progress you need to keep**. SQLite migration and persistence still need testing on a physical phone with a compatible in-place update. A stable private signing key is required before production.

The game works offline. Progress is stored on the device and is not synced between devices. Notifications are optional and off by default. Original game by [tanuu5](https://github.com/tanuu5/tanuki-rush), MIT license; this edition adds the Android shell and gameplay/progression changes.
